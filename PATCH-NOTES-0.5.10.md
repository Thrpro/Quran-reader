# Quran Mushaf Reader — review build 0.5.10

This local review continues the 0.5.9 auto-hiding bottom player. Public v0.5.0 corresponds to internal v0.5.4; PATCH-NOTES-0.5.8.md preserves the cumulative earlier improvements and PATCH-NOTES-0.5.9.md describes the player experiment. Existing releases and backups are preserved.

- Reduce contextual-text drawing storage by omitting provably transparent rows at standard and 125% display density. Conservative bounds cover every supplied path/control point on all 604 shaped pages. Integer cropping keeps the original viewport, glyph positions, resolution and pixels. A precise 2D presentation avoids extra layout rounding. The established high-density path is retained because software rendering samples transformed cropped surfaces differently there.
- Keep each mounted line's canvas and observers across theme and layout changes. Repaint only changed geometry/ink. Draw visible pages first, yield between optional preview batches, and finish a preview synchronously before copying it into a fold. Four full-quality neighboring previews remain available for normal page turns.
- Limit released canvas storage to 32 MiB as well as 60 entries and a 1.5-second expiry. Active pages and folds retain their original resolution. This budget describes unused application buffers, not total WebView2 RAM.
- Make opening pages wait only for the supplied fonts they need. Prepare heading fonts after ordinary pages open; pages containing headings still wait for those fonts. Startup metadata requests have a 15-second timeout, cancellation and localized retry. A required-font failure offers Reload app while preserving the saved reading position.
- Stop the clip engine's watchdog while paused, finished or disposed. Permanent clip failures get four automatic retries after the initial attempt, then wait for a user action. Buffered recitation can finish naturally. Retry preserves the healthy media timeline, speed, exact failed verse and current offset; terminal decoder errors use the existing rebuild path. Recordings are not transcoded and natural pauses are retained.
- Memoize reciter choices/ranking between playback updates. Keep combobox results out of the Tab sequence and retain input focus after pointer/keyboard selection in Arabic and English.
- Add source-wide cropping checks, exact cropped/full-canvas pixel comparisons, lifecycle/startup recovery regressions and real-MSE outage/retry checks. Extend the existing Actions workflow and release checks to run the new regressions. Hosted confirmation and manual installed-app listening remain necessary.
- Update the existing Vite development tool from 7.3.6 to 7.3.7 after the dependency audit identified Windows editor-launch advisories. The lockfile is updated and npm/OSV checks pass. Vite is not included in the installed application. See the [publisher advisory](https://github.com/vitejs/launch-editor/security/advisories/GHSA-587h-7wmj-h5pm).

No framework or dependency was added. Quran text, fonts, outlines, recordings and source page resources are unchanged. Measurements and their limits are documented in MEMORY-PERFORMANCE.md; BUILD-VERIFICATION.md records validation scope. The pre-change source and portable app are under outputs/backups/performance-from-0.5.9-2026-10-21. This work does not commit, push or publish a release.
