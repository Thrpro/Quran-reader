# Slint reader prototype 0.13

A separate Windows prototype using Slint 1.18.1 controls and the unchanged native DirectWrite/Direct2D Quran renderer. It does not replace the production reader or migrate its profile.

## Run

Open QuranMushaf.SlintReader.exe from the application folder. Keep the verified resource pack in Resources beside it. The matching Microsoft Visual C++ x64 runtime must already be installed; this package installs no SDK or system component. To reuse an existing verified resource pack, pass `--resources C:\path\to\Resources`. Selecting an arbitrary directory does not authenticate it. Retain the resource integrity manifest and provider notices.

## Reading and study

Navigate by page, Previous/Next or arrow keys while the reading canvas has focus. Arabic and Persian page digits are accepted. Search supports text, references, surahs, pages, juz, hizb and quarter-hizb. Search and settings overlay the reading canvas. Tafsir reserves a separate locale-aware column so its text does not cover the Quran; compact windows may use the native single-page layout. Menus follow the interface language. Escape closes overlays; Escape also leaves full screen from the reading canvas. A labelled Exit full screen action is available.

Hover over a verse for a subtle highlight. Right-click for study, listening and bookmarks; opening tafsir with a left click is an optional setting, disabled initially. The popup clamps within the canvas. Arabic has bundled Al-Mukhtasar and Al-Saadi tafsirs; English has Saheeh International translation. Source changes preserve the selected verse. Study includes text-size controls and visible scrolling. Optional Follow recitation advances study automatically; manual verse navigation disables it. A different recited verse receives the native recitation outline while the study verse retains its fill. Original renderer rules apply when both are the same verse.

Themes, script mode, clock, page view, motion, position and bookmarks persist in an isolated portable SlintProfile beside the executable. `--profile <directory>` selects another local profile. The production profile is never opened. State is bounded to 64 KiB, validated and saved through native pinned/atomic I/O. An exclusive lifetime owner prevents competing preview instances from overwriting one profile. Invalid/inaccessible state falls back to session-only use without silently repairing malformed files. Bookmark feedback expires after 2.4 seconds without reflow.

## Listening

Listen from a selected verse to the end of its surah or enable This ayah only. The unchanged native engine supplies decoding, fixed providers, URL validation and cache bounds. Playback requires an explicit Play action. The floating player offers timing, seeking, back/forward ten seconds, Pause/Resume, Current ayah and explicit End. Minimize moves controls to the toolbar. Opening study places transport controls in a separate footer inside its column, outside the scrolling text. Listening settings provide reciter, speed, Remember speed and a volume slider with 0%/100% endpoints. Fresh recitations start at 1x unless Remember is enabled or speed was deliberately chosen before Play.

Timed native providers (currently Yasser Al-Dosari and Mishary Alafasy) show validated whole-surah position/duration. Other providers explicitly show their ayah recording clock. Durations are never estimated from ayah count. Last valid timing survives transient decoder/rate states. Seeking earlier than the original selected verse replans the same recording from its beginning, muted and paused until the actual seek is confirmed, then restores playback state. Bismillah highlighting follows verified native opening clips; continuous-recording timing gaps are not inferred as Bismillah.

Ordinary listening keeps the native bounded temporary cache and roughly three-minute preparation policy. It does not promote listened audio to permanent downloads. Audio lives beneath the preview profile. Slint download-management UI is not included in this iteration.

## Architecture and validation

main.rs owns Slint and the bounded coalesced worker; reader.rs adapts the native raster/hit path; controls.rs binds actions; audio_bridge.rs owns the lazy UI-thread native player; preferences.rs owns isolated persistence. Native modules are reused by path without edits. Slint does not shape, substitute or normalize Quran glyphs.

The render worker owns its COM apartment/resources. Only pixels, coordinates and strings cross threads. Stale generations and errors are rejected. Resize work debounces; each transferred image is bounded to 32 MiB. The last committed image remains visible during preparation with stale hits disabled. Closing signals and joins the worker. Transport updates rerasterize only when a verse/opening highlight changes. Idle reading has no playback timer; the optional clock redraws only on minute changes. These are architectural limits, not FPS guarantees.

The app selects winit/skia, which uses the GPU and falls back to software by itself when no GPU surface can start. Options has a Use software rendering setting that applies at the next launch, and `--renderer gpu` or `--renderer software` overrides it for one run. An earlier automatic GPU presentation path consumed about one CPU core while idle on this PC. That did not reproduce in 0.13 testing, but its original cause was never found, so the override stays. See the 0.13 notes for measurements.

Build with Rust 1.92+, the Windows x64 MSVC linker/SDK and sibling native sources. Use Cargo build/test/clippy with --release --locked --target x86_64-pc-windows-msvc; strict Clippy uses --all-targets -- -D warnings.

--qa-output <new-directory> runs eight reading cases and exact native/composed RGBA comparisons, real hits/search and overlay geometry. Four application scale overrides exercise 100/125/150/200%; these are not physical mixed-monitor DPI tests. --qa-audio <new-directory> <original-r92-s112-bundle> checks muted offline native decoding. --qa-player <new-directory> <original-r92-s112-bundle> checks actual main-window callbacks/player/study. Fixed original recording hashes are required; fresh isolated copies prevent network fallback. See recorded delivery reports for outcomes.

Remaining work includes download-management parity, native fold presentation/shadow parity, onboarding/accessibility parity and physical-device qualification. Screenshots/callback tests do not certify human pointer input, IME, Narrator, hardware audio quality or displayed frame pacing. This is not a feature-complete native-reader replacement.

## Reading interface

The neutral 32-DIP title bar uses quiet menus, a redesigned book icon and vector minimize/maximize/restore/close controls. The same icon is embedded as a Windows executable resource and assigned to the native window. The SDK resource compiler is required when building; set RC to its path on another SDK installation. There is no permanent bottom bar. F11 and the labelled Full screen menu use winit borderless fullscreen; Escape closes a panel first, then exits fullscreen.

Page turns retain the two authoritative native rasters once, then Slint animates clipped page faces and a restrained moving shadow (285 ms in 0.13, 300 ms before). The worker does not compose or upload a new full spread for each page-turn frame. Slint's Winit backend schedules declarative animation redraws from the current monitor's reported refresh rate, including rates above 60 Hz; actual achieved presentation depends on the renderer and hardware. The settled native raster remains exact. Single-page turns use the same retained-texture approach. A running turn is never cancelled or restarted, and later requests wait in a bounded queue; see the 0.13 notes. Reduced motion bypasses the turn. Theme transitions retain the bounded 180 ms software recoloring path and shared UI palette contrast guard. Application redraw intervals and monitor refresh are recorded in motion QA; they are not display FPS measurements.

Tafsir reserves a column; settings/search retain overlays. Page arrows and keyboard navigation return focus to reading. Study's own arrows step the ayah; page navigation closes an obsolete study panel instead of leaving it blank. Study playback stays below the scrollable body. The reciter popup remains a quiet list, with a clear End action and current-ayah tooltip.

QA includes native-pixel comparisons, reserved-column geometry, intermediate fold frames, real native fullscreen entry/exit, embedded icon loading and muted real-decoder/player checks. Software scale overrides are not physical mixed-monitor tests. Minimize/reopen recovery and sustained displayed-frame pacing still need manual qualification on the user's hardware.

Theme inversion uses the native palette contrast guard over coverage from the prepared original grayscale pixels. The custom UI palette also protects foreground contrast during inversion. A regression samples all three-theme pairs across the transition; final endpoint pixels remain exact.

New profiles start with contextual elongation enabled and show a language introduction, which can be reopened from Options. Existing saved choices are preserved. Search opens on a surah list and supports numeric surah and page results. A pointer highlight follows the original native verse hit regions without rerendering the Quran, including beside tafsir. Full screen hides the title bar and provides an exit control and compact navigation rail. Saheeh International footnotes are separated with a heading; inline markers retain the original flattened source text.

Corner dragging follows the pointer at each outer page corner. Short drags return to the original spread; longer drags commit. Hover uses a stronger green/olive accent. Tafsir navigation keeps an already visible spread. Closing tafsir retains its content through the exit animation. Global shortcuts default to Ctrl+F for Search, Ctrl+L for Listen, Ctrl+, for Options, Ctrl+Space for playback and F11 for full screen. Options contains saved alternative key combinations for Search, Listen and Options. These are selectable presets rather than arbitrary key recording.

In 0.8 the hover uses native-colour background patches with the original opaque ink preserved and antialiasing recomposited, rather than a translucent tint over glyphs. Only the hovered verse patches are prepared once per verse and native render; no full-page rerender occurs on pointer movement. Page turns now clip the retained and reverse faces along a diagonal crease and rotate the readable reverse texture, using the existing native paper geometry. The earlier WebView implementation used StPageFlip2.0.7; this preview uses Slint clipping/transforms and the native geometry, not its JavaScript runtime. Click an outer edge (including its middle) to turn or drag inward. Navigation groups follow the interface direction. Options controls have minimum layout sizes and visible keyboard-focus styling.

In 0.9 a destination page is kept in a separate texture during preparation and folding; the settled book image changes at completion. Corner-start QA compares visible pixels before movement and checks the far page during a small lift. Source selectors are bounded to 36 DIP and do not stretch vertically. Options and tafsir put their scroll track in a separate left gutter. The verse context menu uses compact icon rows, and the title bar uses quieter text and selection colours.

Fold faces now clip full native textures in layout coordinates. They do not split source images using integer pixel crops, which rescaled odd-width spreads and changed the visible far page during a tiny lift.

The retained face is the original settled image itself. The fold overlays only the newly exposed source area and rotating reverse face, so untouched content does not pass through a transformed repaint at higher DPI.

In 0.10 the worker prepares two adjacent spreads ahead of navigation, retaining native hit maps with each raster and keeping the active map intact. The adjacent pixel cache is limited to 24 MiB and exact presentation keys. Large surfaces can reduce the number of cached neighbors. A first-paint gate holds turn progress at zero before motion. Only explicit reading navigation starts a fold; tafsir opens with the side-panel transition. The title-bar navigation and shorter brand are grouped compactly on the right in both languages.

In 0.11 fold geometry is a pure synchronous binding of the current progress and dimensions. The former changed callback could publish geometry after the pointer's frame. Drag distance now matches the native corner's full travel instead of reaching a completed fold after only half a leaf. Diagnostic flat faces are compared with the independent native retained/reverse polygons at four progress values, in both directions, top/bottom and single/spread layouts. A full held drag is also checked against the destination raster before release. These are renderer snapshot checks, not a displayed frame-rate guarantee.

The exposed page image is explicitly anchored at y=0 inside its oversized clipping container. Slint's implicit centering moved that image away from the revealed area, leaving the old page visible until landing. A small diagnostic reproduction demonstrated the mismatch and the corrected intermediate faces independently of the full reader.

Panels animate a normalized reveal relative to their own entrance edge. Opening tafsir after a hidden centered search panel cannot interpolate from that old central position. The title bar is 30 DIP with smaller icons and outlined branding. Onboarding is limited to the reading area; caption controls remain enabled. QA dispatches pointer events to maximize, restore and minimize while the introduction stays open, then restores the owned test window. Physical taskbar recovery and mixed-monitor behavior still need hardware qualification.

In 0.12 the title bar is 28 DIP. The app identity stays on the left; navigation is beside it in English and moves to the right in Arabic. Caption targets retain their 44 DIP width. Full screen moves into Options while F11, Escape and the labelled fullscreen exit remain available. Reading options have grouped controls, compact navigation rows and a collapsed shortcut disclosure.

Search uses a compact segmented category strip, numbered bilingual rows and a separate left scroll gutter. Old rows remain visually steady while a query runs but cannot be activated until the validated results are ready. Up/Down select a result, scroll it into view and Enter opens it through the same guarded callback as a click. Opening Search retains input focus rather than returning it to the reading canvas. Source Quran rendering, adjacent caching and fold behavior are unchanged from the verified 0.11 implementation.

In 0.13 page turns use the GPU by default. Over 30 maximized 1920x1080 turns at 144 Hz, software rendering gave an 18.4 ms median and 36.7 ms 95th-percentile redraw interval, and the GPU gave 6.9 ms and 8.3 ms with less CPU. A settled-page screenshot comparison between the two renderers found no differing pixels in any verse line on the one spread compared, and idle CPU stayed under 0.1% on both. The cost is memory: the GPU path holds roughly 240 MiB working set instead of roughly 100 MiB. These results come from one PC with AMD and NVIDIA graphics and are not a guarantee for other hardware.

Motion follows the earlier WebView reader, whose feel remains the reference: ease-out timing of 285 ms, 175 ms while more turns are waiting, and a released drag animates only its remaining travel with a 130 ms minimum. turn_queue.rs holds these rules. Arrow keys and page buttons pressed during a turn wait in a queue of at most ten. Key-up and focus loss discard auto-repeated entries, so a held key stops at release while deliberate taps are kept. Reversing direction abandons turns waiting in the old direction. Jumps, resizes, setting changes, drags and open panels clear or bypass the queue.

The back of the turning sheet has soft shading mirrored by turn direction, and a one-sided 32 DIP shadow falls on the revealed page, clipped to the rounded paper frame. Native polygon checks turn this shading off through fold-shading because they compare flat diagnostic faces.

QA adds maximized-motion-qa.json: eight uninterrupted maximized turns, requiring at least 16 redraws, a 95th-percentile redraw interval within 25 ms, and at least 20% progress 40 ms after first movement. These limits are enforced on the GPU renderer and only recorded on software. They measure application redraw requests, not displayed frames. page-turn-shaded-0.png and page-turn-shaded-1.png capture a held mid-turn in both directions for visual review. QA phase numbers above 9300 belong to this check.
