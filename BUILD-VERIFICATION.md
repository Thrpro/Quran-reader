# Build verification for 0.5.8

The GitHub clone was checked using the existing locked dependencies and local compiler caches: Quran/study asset validation, the generated ayah map, 90 unit tests, TypeScript/Vite production build, 5 native tests, Rust release build and packaged-web file verification. This is not a pristine-PC installation test. No public release or source commit is created by these checks.

Browser checks use isolated Edge profiles and authentic local audio fixtures. They cover reader navigation, retry after page failures, search/study, keyboard ayah actions and focus, source quotation integrity, contextual ink/fold copies, playback speed, pause/resume, range repetition, continuation without restarting, downloads with timing metadata, seek, saved preferences and resume. Both the browser shell and native title-bar layout are covered. The side player leaves page sizes unchanged; narrow layouts retain compact controls.

Contextual artwork is compared with the supplied SVG outlines and fold copies are compared with current canvas pixels at device scales 1, 1.25 and 2. Reduced motion mounts no preview artwork; normal motion retains four previews. These buffer counts are not total WebView2 process-memory measurements. Historical 0.5.7 process measurements and their limits remain in MEMORY-PERFORMANCE.md. This version makes no new hardware CPU/GPU percentage or universal RAM-ceiling claim.

Offline/recovery tests cover missing or corrupt timings, quota failures, incomplete MP3s, temporary failures, bounded retry, exact position/speed/pause preservation and premature playback-end events. Fixtures and simulated failures do not establish live-provider uptime or replace manual listening review. Live provider checks and their sampled scope are described in AUDIO-PROVIDERS.md.

The production web build records its source/content fingerprint. The native builder refuses stale source or modified web output, and the portable packager verifies all payload files and the completed ZIP without overwriting an existing archive. RUST-HOST-BUILD.json records the source commit, dirty state, content fingerprint and tool versions; this provides traceability rather than a guarantee of byte-identical compiler output across machines. The reviewed portable ZIP is built from this clone and retains its current uncommitted-source identity.

The first hosted GitHub Actions run remains necessary to validate its runner environment. CI stores test artifacts and does not publish them automatically. Automated checks complement manual reading/listening and installed-app review.

Follow-up on 2026-10-18: the first hosted run passed asset validation and 80 of 81 tests, then failed the temporary Git-repository identity test. A matching failure was reproduced locally through a Windows directory alias. Git and Node can report different path spellings for the same folder; source-root comparison now resolves both paths before comparing them. New tests cover aliased Git checkouts and exports nested inside another checkout. All 83 unit tests and asset checks pass locally. The hosted run must be repeated on the fix commit; this is not a reported CodeQL vulnerability.

The next hosted run (#12) passed the earlier build/unit stage and reached browser verification, where a fixed minimum frame count during a short swipe failed. The runtime check now samples held intermediate pointer positions and verifies monotonic fold progress, changing geometry, completed navigation, bounded previews and idle cleanup. Button turns still require animation callbacks. Frame intervals are diagnostic and include automation delays; they are not an FPS pass/fail threshold. The revised browser suite passed locally with the repeated-fold section at normal speed and sixfold CPU throttling. The clock-boundary fixture installs its fake timers before loading a separate reader page. Failures now retain a JSON report. The complete hosted workflow still needs a successful run on this follow-up commit.

Hosted run #13 passed runtime verification and failed the binary SVG/canvas overlap cutoff. Edge with GPU rendering disabled reproduced its exact DPR-1 measurements locally: mean error 1.847995075372568, overlap 0.9181484617555744, and 3889 bright pixels. The comparison now allows a one-physical-pixel antialias edge halo in both directions, requires zero unmatched foreground pixels, centroid displacement below half a pixel, ink mass within five percent, and the original mean-error limit below 3. Raw overlap remains diagnostic. Seven synthetic geometric tests reject real shifts, missing marks, extra lines, reduced contrast and empty/mismatched images. Authentic-artwork checks pass with normal and software rendering at device scales 1, 1.25 and 2. Failure reports and comparison PNGs are retained in CI. Application rendering and Quran resources are unchanged; a successful hosted run on this fix remains necessary.

Hosted run #14 failed the remaining aggregate frame-count assertion before reaching artwork verification. A minimal local reproduction showed that Playwright's context-wide clock setup can overwrite the requestAnimationFrame counter while callbacks continue to run: eight delivered callbacks produced an empty observer log. The animation context now keeps native timers, and the minute-boundary clock check runs in a different BrowserContext. Probe-identity guards run after navigation and after the isolated clock test. Each of four held pointer positions captures geometry inside its second delivered browser frame, checks ordered frame timestamps and changing progress/geometry, and then checks committed pages, bounded previews and idle cleanup. Aggregate callback counts are diagnostic, not a fixed pass threshold. Reintroducing the previous clock setup in a negative-control copy fails the new instrumentation guard explicitly. All 90 unit tests and asset checks pass; the native-timer runtime suite passes locally in normal rendering and with software rendering plus sixfold CPU throttling of the repeated-fold section. The application code and authentic resources remain unchanged, and hosted confirmation is still required.
